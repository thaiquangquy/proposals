Both cameras take a photo at the same time, every 7 seconds. No photo is lost when the internet stops.

A small Linux computer on the site (the edge box) tells both cameras to take a photo at the same time. It saves each photo on its local disk first. Then it sends the photo to cloud storage when the internet is available.

Answers to your five questions

Each answer starts with the short answer. The sections below give the details.

  1. What camera hardware would you recommend and why?

    Use any outdoor PoE camera with approximately 8MP or more and RTSP support.

    Use an outdoor PoE camera that meets these two requirements:

    • Resolution. The camera must give high-resolution photos, approximately 8MP (4K) or more. Camera A must have a 180° view. Camera B can also have an optical zoom.
    • RTSP support. The edge box uses the RTSP address of the camera (rtsp://…) to get a photo from the video stream. Almost all IP cameras support RTSP. If the camera also has an HTTP or ONVIF snapshot address, the edge box uses that address first. This address gives the full-quality JPEG photo, and the edge box does not decode video.

    Examples that meet both requirements: the Reolink Duo 3 PoE (16MP, dual-lens, 180°) for Camera A and the Reolink RLC-811A (8MP, 5× optical zoom) for Camera B. Both are low cost and outdoor-rated, and both have an HTTP snapshot address.

    You select the final camera models. Each camera is one address in a configuration file. Thus, you can use any brand that meets the two requirements. The hardware table below shows the cost of these examples.

  2. How would you keep two cameras synchronized?

    One scheduler on the edge box triggers both cameras at the same time, and the system pairs the photos by slot number.

    At each 7-second step, the edge box sends the photo request to both cameras at the same time.

    Each step has a number, the slot (slot = floor(unix_time / 7)). The two photos from one step get the same slot number. The system pairs the photos by the slot number. It does not compare timestamps to find pairs.

    The edge box also keeps the correct time. It gets the time from internet time servers with NTP (Network Time Protocol). The edge box sends this time to the two cameras. Thus, the time that each camera writes on its photo agrees with the database. This also operates when the internet is not available.

    The edge box also measures the real time between the two captures. For each photo, it records the time when it sent the request and the time when the first byte of the photo came back. The camera took the photo between these two times. For each slot, the system compares the two cameras. If the difference is more than 1 second, the system sends an alert. Usually, the difference is less than 0.5 seconds. I will measure the real value with your hardware in week 1.

    The edge box does this measurement with its own clock, which has millisecond precision. Many cameras record the photo time only to the full second, so the camera time cannot measure a small difference.

  3. Would you trigger snapshots from an edge computer or through the cameras themselves?

    From the edge computer, because one scheduler and one clock make each photo pair exact.

    If each camera uses its own schedule (FTP upload or SD card timer), each camera uses a different clock. Some cameras also have a minimum interval. Then it is difficult to pair the photos. With the edge box, there is one scheduler, one clock, one log, and one location to change the interval.

    Risk: if the edge box stops, the capture stops. To decrease this risk, the design uses a hardware watchdog, an automatic start after a power failure, and a heartbeat alert. As an option, each camera can also save a photo to its SD card at a longer interval. Thus, the site keeps some photos if the edge box fails.

  4. How would you handle several hours of internet outage without losing images?

    The edge box saves each photo to its local SSD first and uploads it when the internet is available again.

    The capture does not wait for the network.

    Each photo stays on the SSD until its upload succeeds. When the internet is available again, the edge box sends the newest photos first, then the older photos. A 6-hour outage needs approximately 14 GB. A 512 GB SSD keeps more than one week of photos. Refer to the edge box diagram in The system.

  5. What similar camera/IoT systems have you built?

    I worked on a CCTV platform with Hikvision and ONVIF cameras, camera time sync, camera status and time-range playback.

    I worked on a Windows CCTV and video management platform. It connects to Hikvision cameras (Hikvision SDK) and ONVIF cameras. It has device time synchronization, online/offline status for each camera, and video playback for a time range. Refer to Relevant past work. I also have approximately 10 years of experience with embedded C++, IoT data pipelines, and AWS (S3, SQS, Lambda, RDS, PostgreSQL).

Inside the edge box: store first, send later

-- one row for each photo; the file is in R2
CREATE TABLE capture (
  camera_id     text,
  slot_ts       timestamptz,  -- same for A and B
  sent_at       timestamptz,  -- request sent
  first_byte_at timestamptz,  -- photo starts
  camera_ts     timestamptz,  -- camera clock
  object_key    text,
  bytes         int,
  sha256        text,
  upload_status text,
  PRIMARY KEY (camera_id, slot_ts)
);
-- A and B from 2:15 PM to 2:25 PM
SELECT slot_ts,
  max(object_key) FILTER
    (WHERE camera_id='A') AS a,
  max(object_key) FILTER
    (WHERE camera_id='B') AS b
FROM capture
WHERE slot_ts BETWEEN
  '2026-10-12 14:15' AND '2026-10-12 14:25'
GROUP BY slot_ts ORDER BY slot_ts;

The primary key is also the index for the time-range query. A 10-minute range gives approximately 86 pairs of photos. The viewer opens each photo with a signed URL that is valid for a short time.

Failure conditions

These are also the acceptance tests. I will do each test and record the result in the handover document.

FailureSystem response
Internet failure for many hoursThe capture continues to the SSD. When the internet is available again, the upload starts. It sends the newest photos first, then the older photos. No photos are lost.
Power failureThe BIOS starts the box again. systemd starts all services. SQLite WAL and the safe file-write sequence prevent incomplete photos. The UPS supplies power during short failures.
Camera restart or disconnectionThe edge box tries again at longer intervals. The system records each missing slot as a gap, so the timeline shows the gap. The edge box sends a device status record to the cloud.
Edge software stopsThe systemd watchdog restarts the service. If the operating system stops, the hardware watchdog restarts the box.
Disk fullThe cleanup job deletes uploaded photos first, oldest first. An alert starts at 80% full.
Clock errorchrony keeps the edge box time correct with NTP. The cameras get their time from the edge box. Thus, the time on each photo agrees with the database.
Slow cameraFor each slot, the edge box measures the time between the two captures with its own clock. If the time is more than 1 s, the system sends an alert. The usual causes are a slow camera (autofocus, day/night change) or a slow network.
No data from the siteThe edge box sends a heartbeat each minute. If a heartbeat does not arrive, you get an email alert.
